# Snapshot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Choosing still GIF, PNG, JPEG or BMP takes one image of the framed area instead of recording.

**Architecture:** Image formats are extra `OutputFormat` values. A `Snapshot` class grabs and encodes; `ApplicationWindow` branches to it where recording would start, then rejoins the existing save path (`in_file`/`out_file`). `ScreenRecorder` is untouched.

**Tech Stack:** Vala, GTK 3 / GDK / gdk-pixbuf, ffmpeg (still GIF only), meson.

**Spec:** `docs/superpowers/specs/2026-11-24-snapshot-design.md`

## Global Constraints

- No new dependency. GTK >= 3.20, meson >= 0.47.
- Setting values: `still-gif`, `png`, `jpeg`, `bmp`. Extensions: `gif`, `png`, `jpg`, `bmp`. JPEG quality 95.
- Full device resolution, no pointer, no downsample.
- Image formats disabled when `DesktopIntegration.is_wayland ()`; still GIF also without ffmpeg.
- Animated recording behaves exactly as before.
- All user-visible strings go through `_ ()` / `translatable="yes"`. No attribution lines in commits.
- `B` is a meson build directory outside the repo. Build: `ninja -C $B`. Tests: `meson test -C $B` (6 pass at baseline).

## Review Focus

- Remembered image format on Wayland or without ffmpeg: falls back to animated GIF, no crash (Task 3).
- Start delay: the last countdown digit must not be in the image (Task 3).
- Window closed or Stop pressed during the delay: no grab, no dialog, next snapshot works (Task 3).
- Preferences opened while an image format is selected: combo shows it and does not reset the setting (Task 1).
- Frame partly off-screen: image is the visible part; nothing visible gives an error dialog (Task 2, Task 3).

### Task 2: Grab and encode

**Files:** Create `src/recording/snapshot.vala`, `tests/test-snapshot.vala`. Modify `src/meson.build`, `tests/meson.build`.

**Interfaces — Consumes:** Task 1 enum, `Utils`, `RecordingArea`, `CliPostProcessor.spawn_command_async`.
**Produces** (namespace `Peek.Recording`):

```vala
public class Snapshot : Object {
  public static bool is_format_available (OutputFormat format);  // image formats only
  public static Gdk.Pixbuf grab (RecordingArea area) throws RecordingError;
  public static async File encode (Gdk.Pixbuf pixbuf, OutputFormat format) throws RecordingError;
}
```

- [ ] **Step 1: Failing test** `/snapshot/encode`: 64x48 RGB pixbuf filled `0xff0000ff`, for each image format run `encode` in a `MainLoop`, then assert the file loads with `new Gdk.Pixbuf.from_file` at 64x48, `Gdk.Pixbuf.get_file_info` names `png`/`jpeg`/`bmp`/`gif`, and a middle pixel is within 4 of (255,0,0). Delete the files. Skip still GIF with `Test.skip` if ffmpeg is missing. Must not need a display.
- [ ] **Step 2: Failing test** `/snapshot/grab-empty`: an area with `width` 0 throws `INITIALIZING_RECORDING_FAILED`.
- [ ] **Step 3: Implement.**
  - `grab`: reject width or height < 1 first. Divide all four area values by the widget's scale factor and call `Gdk.pixbuf_get_from_window (Gdk.get_default_root_window (), ...)`; null is an error.
  - `encode`: `Utils.create_temp_file`, then `pixbuf.savev` with `quality`=`95` for JPEG only. Still GIF: PNG temp, then ffmpeg `-y -i in.png -filter_complex split[a][b];[a]palettegen[p];[b][p]paletteuse out.gif`, through a small private `CliPostProcessor` subclass. Remove temp files on failure, and the PNG always.
  - `is_format_available`: false on Wayland; still GIF also needs ffmpeg on the path.
- [ ] **Step 4:** Build and tests pass.
- [ ] **Step 5:** Commit `feat(recording): Grab and encode a snapshot of the recording area`.

**Interfaces — Consumes:** Task 1 and 2.

- [ ] **Step 1: UI.** In `pop_format`, add dim labels "Record animation" and "Take snapshot" and radio buttons `still_gif_button` (label "GIF"), `png_button`, `jpeg_button`, `bmp_button` in group `gif_button`, same handler, positions renumbered. - [ ] **Step 3: Availability.** On construction, set unavailable radio buttons insensitive; in `update_format_label`, if the format is an image format and unavailable, set `OutputFormat.GIF`.
- [ ] **Step 4: Capture.** In `start_recording ()`, if the format is an image, call `take_snapshot ()` instead. It latches the format (preferences may change it while the dialog is open), hides `size_indicator`, `shortcut_label` and `delay_indicator`, sets `start_recording_event_source` to a 200 ms `Timeout` (compositor redraw; commented as a tunable constant), and then: clear the source id, grab, set `is_postprocessing`, disable the Stop button, encode, set `in_file`, `show_file_chooser ()`. Set `in_file` before the dialog, so the existing `try_save_file` runs on accept and `leave_recording_state` deletes the temp file on cancel. Do not call `recorder.cancel ()` or `recorder.record ()` in this path. Errors: existing `ErrorDialog` with "The snapshot could not be taken.", then `leave_recording_state ()`.
- [ ] **Step 5: Build, then verify on a private display** with `xvfb-run -d` and xfwm4 compositing, a temporary `GSETTINGS_SCHEMA_DIR` and `GSETTINGS_BACKEND=memory` or a throwaway `XDG_CONFIG_HOME`, never the user's settings or running Peek (use `dbus-run-session`). Put a known colour behind the frame, drive with `--start` and xdotool, record raw output for:
  - each format: `file` type, size equals the area, only background pixels; GIF has 1 frame (`ffprobe -count_frames`)
  - the same with start delay 1: no digit
  - Stop during the delay, window close during the delay, Cancel in the dialog: no file, no leftover in `~/.cache/peek`-equivalent, next snapshot works
  - frame partly off-screen: the visible part; `GDK_SCALE=2`: device resolution
  - `WAYLAND_DISPLAY=x` and PATH without ffmpeg: entries disabled, fallback to GIF
  - preferences opened with `png` selected: still `png` afterwards
  - animated GIF recording still saves a multi-frame file
